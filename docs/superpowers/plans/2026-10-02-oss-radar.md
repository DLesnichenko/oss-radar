# OSS Radar Implementation Plan

> **Note:** written before the project moved to its own repository. Paths starting with `github_trend_radar/` refer to the root of this repository.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A public, login-free dark/cyan dashboard of fast-growing GitHub projects, fed by a daily GitHub Actions collector and served from GitHub Pages.

**Architecture:** A stdlib-only Python collector writes daily star snapshots and computes `data/radar.json`; a no-build vanilla HTML/CSS/JS UI reads only that file. Pure logic on both sides (`metrics.py`, `classify.py`, `assets/logic.js`) is unit-tested; I/O (GitHub API, Claude API) goes through injectable transports.

**Tech Stack:** Python 3.10+ (stdlib + pytest), vanilla JS (ES modules) tested with `node --test`, inline SVG charts, GitHub Actions + Pages.

**Spec:** `docs/superpowers/specs/2026-10-02-oss-radar-design.md`

## Global Constraints

- All project files live under `github_trend_radar/` (published from its own GitHub repo later).
- No login, no password, no "Выйти" button anywhere.
- Collector: Python stdlib only (no `requests`); tests use pytest.
- UI: no build step, no npm dependencies; reads only `data/radar.json`.
- UI copy in Russian. Name "OSS Radar", header "Что растёт в open source". Dark theme, cyan accent (`--bg:#0b1220; --surface:#111a2e; --accent:#22d3ee`).
- Tabs, in order: Практика, Рейтинг проектов, Вертикальные агенты, Сегменты и динамика; plus a Методология page.
- Shared filters on every tab: snapshot date, trend (category), status, language, search.
- Growth windows 7/30/90 days; acceleration = growth over last 30 days ÷ growth over previous 30 days.
- Statuses (exact strings): `ускоряется`, `устойчивый рост`, `рост без ускорения`, `замедляется`.
- Categories (exact strings): Оркестрация агентов, Навыки и методологии, Контент и дизайн, Экономия и контекст, Веб и инструменты, Вертикальные агенты, Прочее.
- Works without `ANTHROPIC_API_KEY`; with it, "для чего нужен" is rewritten from the README via Claude API.

## Review Focus

Failure modes the spec implies that a user will hit (each has a test in the task named):

1. Repo younger than the growth window — growth equals total stars, not "н/д" (Task 1).
2. Gaps in daily snapshots (Action skipped days) — metric is `null`, UI shows "н/д" instead of a wrong number (Tasks 1, 5).
3. GitHub rate limit or a repo that was deleted/renamed (404) — run must not write a half-empty snapshot; a 404 skips only that repo (Task 4).
4. Filters that match nothing — UI shows "Ничего не найдено", not a blank page (Tasks 5, 6).
5. Repo descriptions are untrusted text — must be HTML-escaped before rendering (Task 5).

### Task 1: Metrics module

**Files:**
- Create: `github_trend_radar/collector/metrics.py`
- Test: `github_trend_radar/tests/test_metrics.py`

**Interfaces:**
- Produces (all `History = dict[datetime.date, int]`, star count per snapshot date):
  - `stars_at(history, day, created=None, max_gap_days=3) -> int | None` — 0 if `created` is set and `created > day`; else stars of the latest snapshot `<= day` if it is within `max_gap_days`, else `None`.
  - `growth(history, day, window, created=None) -> int | None` — `stars_at(day) - stars_at(day - window)`; `None` if either is `None`.
  - `acceleration(history, day, created=None) -> float | None` — `growth(30) / prev30` where `prev30 = stars_at(day-30) - stars_at(day-60)`; `None` if any part is `None` or `prev30 <= 0`.
  - `status(growth30, accel) -> str | None` — `None` if `growth30 is None`; if `accel is None`: `"ускоряется"` when `growth30 > 0` else `None`; otherwise `>=1.5` ускоряется, `>=0.8` устойчивый рост, `>=0.4` рост без ускорения, else замедляется.
  - `active_days(history, day, span=30) -> int` — count of snapshot dates in `(day-span, day]` whose stars exceed the previous snapshot's.
  - `weekly_gains(history, day, weeks=10, created=None) -> list[int | None]` — 7-day growth for the week ending `day - 7*(weeks-1-i)`, oldest first.

- [ ] **Step 1: Write failing tests** covering: `stars_at` picks latest snapshot ≤ day; returns `None` when the nearest snapshot is 4 days old (gap rule); returns 0 before `created`. `growth` for a repo created 10 days ago with a 30-day window equals its current stars (focus 1). `acceleration` is `None` (no ZeroDivisionError) when previous 30 days had zero growth. `status` boundaries at exactly 1.5, 0.8, 0.4. `active_days` counts only increasing days. `weekly_gains` returns `None` entries where history is missing.
- [ ] **Step 2: Run** `cd github_trend_radar && python -m pytest tests/test_metrics.py -v` — expect FAIL (module missing).
- [ ] **Step 3: Implement** the six functions above in `collector/metrics.py` (pure, no I/O; `datetime.timedelta` arithmetic).
- [ ] **Step 4: Run** the same command — expect all PASS.
- [ ] **Step 5: Commit** `git add github_trend_radar && git commit -m "Add star growth metrics"`.

### Task 4: GitHub collector and backfill

**Files:**
- Create: `github_trend_radar/collector/collect.py`, `github_trend_radar/collector/watchlist.json` (`{"repos": [str]}`, seed with ~10 well-known agent/skill repos)
- Test: `github_trend_radar/tests/test_collect.py`

**Interfaces:**
- Transport: `Http = Callable[[str, dict], tuple[int, dict | list, dict]]` (url, headers → status, json, response headers). Default implementation uses `urllib.request` with `Authorization: Bearer $GITHUB_TOKEN` when set.
- Produces:
  - `class RateLimited(Exception)`
  - `search_candidates(http, queries: list[str], limit: int) -> list[str]` — repo full names from `/search/repositories?sort=stars`.
  - `fetch_repo(http, full_name) -> dict | None` — snapshot entry; `None` on 404.
  - `collect(http, watchlist: list[str], queries: list[str], limit: int, out_dir: Path, today: date) -> Path` — writes `out_dir/<today>.json`; raises `RateLimited` on 403/429 with `x-ratelimit-remaining: 0` **before writing anything**.
  - `backfill(http, repos, out_dir, today, days=90)` — pages `/stargazers` with `Accept: application/vnd.github.star+json`, and for each of the last `days` days merges `{"stars": n}` into that day's snapshot without overwriting existing entries.
  - CLI: `python collector/collect.py [--backfill]`.

- [ ] **Step 1: Write failing tests** with a fake `Http`: `collect` writes one file with expected entries; a 404 repo is skipped and others kept; a rate-limited response raises `RateLimited` and leaves no file (focus 3); `backfill` yields correct cumulative star counts per day and does not overwrite an existing entry.
- [ ] **Step 2: Run** `python -m pytest tests/test_collect.py -v` — expect FAIL.
- [ ] **Step 3: Implement** `collect.py`; queries come from a `QUERIES` constant (topics agent, skill, mcp, ai-agents), candidate cap 60.
- [ ] **Step 4: Run** tests — PASS.
- [ ] **Step 5: Commit** `git commit -m "Add GitHub collector and star backfill"`.

### Task 6: Pure UI logic

**Files:**
- Create: `github_trend_radar/assets/logic.js`
- Test: `github_trend_radar/tests/logic.test.mjs`

**Interfaces** (ES module exports):
- `esc(s: string|null) -> string` — escapes `& < > " '`; `null` → `""` (focus 5).
- `filterProjects(projects, {category, status, language, query}) -> Project[]` — `""` means "all"; `query` matches repo or purpose, case-insensitive.
- `rankBy(projects, metric: "growth7"|"growth30"|"growth90"|"acceleration"|"stars") -> Project[]` — descending, `null` metric values last.
- `segments(projects) -> {name, count, growth30, growth90, avgAcceleration}[]` grouped by category (sorted by growth30 desc); `avgAcceleration` ignores `null`s, `null` if none.
- `weeklyTotals(projects, weeks: string[]) -> {week: string, gain: number|null}[]` — sums `weekly[i]`, `null` when every project is `null` for that week.
- `fmt(n: number|null) -> string` — Russian thousands separator (non-breaking space); `null` → `"н/д"`.

- [ ] **Step 1: Write failing tests** with `node:test`: `esc("<img onerror=x>")` contains no `<`; `filterProjects` returns `[]` for a non-matching query; `rankBy` puts `null` last; `weeklyTotals` null/partial cases; `fmt(29044) === "29 044"`, `fmt(null) === "н/д"`.
